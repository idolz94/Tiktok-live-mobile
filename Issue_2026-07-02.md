## Stepper tạo vận đơn đang mismatch label/logic

### Vị trí

- [src/features/orders/create-shipment/lib/use-create-shipment.ts:43](src/features/orders/create-shipment/lib/use-create-shipment.ts#L43)

### Hiện trạng

- Label hiển thị: `Số lượng`
- Nút `+`/`−` đang chỉnh `weightInput` (khối lượng gram, bước ±100g)
- Giá trị giữa stepper hiển thị `displayQuantity` (computed từ order products, không có setter)
- `weightInput` là state riêng, mặc định `"500"` gram

### Vấn đề

UI nói là chỉnh `Số lượng`, nhưng logic thực tế lại chỉnh `Khối lượng`. Người dùng thấy stepper không phản ánh đúng hành động.

### Gợi ý

Chưa rõ mục đích sản phẩm. Cần xác nhận UX: stepper này intended để chỉnh `Số lượng kiện/sản phẩm` hay `Khối lượng gói hàng`.

## Live resume 404: `/live-stream/status` không tồn tại trên backend

### Reproduce

Mở browser từ app (ví dụ deep link) → quay lại app.

### Log

```
APP_STATE_CHANGE nextState: "active"
RESUME_TIMER_FIRED
RESTORE_START
API ERROR — GET /live-stream/status → 404 ROUTE_NOT_FOUND
LIVE SESSION STATUS ERROR: ApiError 404
```

### Nguyên nhân

Khi app quay foreground, hook `useTikTokLiveSocket` chạy resume flow:

1. `AppState` listener detect `active`
2. Sau 500ms → `RESUME_TIMER_FIRED`
3. Gọi `restoreOrClearSessionOnForeground()` → `getLiveSessionStatusApi()`
4. API `GET /api/live-stream/status` trả 404 — backend không có route này

### Vị trí code

- Hook resume: [use-tiktok-live-socket.ts:560-637](src/features/tiktok-live/hooks/use-tiktok-live-socket.ts#L560-L637)
- API definition: [sse-api.ts:77-91](src/features/tiktok-live/service/sse-api.ts#L77-L91)
- Error handling: catch block chỉ `console.error`, không crash app

### iOS noise (không phải bug app)

```
RemoteTextInput ... requires a valid sessionID
Snapshotting a view UIKeyboardImpl that is not in a visible window
```

Đây là iOS warning khi keyboard/autofill bị dismiss lúc app chuyển background. Harmless.

### Hành động cần làm

- Xác nhận với backend: endpoint đúng để check live session status là gì (đã đổi tên? cần path param?)
- Chưa nên sửa mobile cho đến khi biết contract đúng
